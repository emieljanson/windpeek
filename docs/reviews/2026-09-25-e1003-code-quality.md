# E1003 production readiness — strict code-quality review

Reviewed the complete uncommitted E1003 readiness change against
`thermo-nuclear-code-quality-review`, then corrected the findings below.
The scope includes firmware, host harness, USB protocol, browser dependencies,
MapLibre worker packaging, browser fixtures and release workflow.

## Findings and resolutions

### P1 — Duplicated navigation state created another synchronization obligation

The initial touch fix copied retained overview/page fields into a separate
atomic input snapshot. Every successful transition had to keep both models in
sync, which recreates the class of defect the fix is meant to prevent.

Replaced all three fields with one retained atomic displayed-view value. Detail,
overview page and uninitialized state have one owner. Navigation, scheduled
refresh and the nonblocking input getter all read it. No publication copy or
bit-mask snapshot remains. Existing simulated reboot, failed display and
background-fetch hit-testing regressions cover the replacement.

### P2 — Calendar recovery logic leaked into application orchestration

The stale-cache fix added nested date/sample matching inside an already large
application file, while overview performed the same timestamp matching in a
separate implementation. Those paths could diverge again.

Moved calendar resampling to the existing `wind_dashboard_data` layer and made
both paths use its timestamp lookup. The application decides when resampling
is needed and which provider timestamp owns freshness; it no longer constructs
the calendar inline. No additional module, runtime mode or generic framework
was introduced. Offline midnight, fifth-day, swell and module-combination
runtime tests continue to cover the behavior.

### P2 — USB transport recovery depended on a side-channel flag

The installer callback set a mutable `frame_handled` flag for its caller to
inspect after parsing. Whether a read recovered a valid frame belongs to the
parser, not persistent installer state.

The internal C parser now returns `wind_usb_feed_result_t`, containing both the
framing error and delivered-frame count. The UART loop can preserve a recovered
session directly from that result. The wire protocol is unchanged. Tests
explicitly cover a framing error and valid frame in the same read, replay
protection after corruption and maximum-size fragmented payloads.

### P2 — Removed cache fallback left redundant identity fields

Overview still stored a separate screen hash and generation time after the
age-based fallback was removed. The source hash already incorporates the
screen/date identity; maintaining both comparisons adds no protection.

Removed the unused timestamp and redundant hash, centralized the identity
comparison used by both availability and display, and bumped the overview
cache format to invalidate old records. Concurrent-publication, date rollover
and corrupted-frame tests cover the remaining exact-match behavior.

### P2 — Memory checking was local evidence rather than a release gate

The full sanitizer suite ran locally but the release workflow did not retain
that check. Added full AddressSanitizer/UndefinedBehaviorSanitizer host testing
to the firmware verification job, with its required zlib development package.
Website publication already depends on firmware and all browser shards passing.

## Other reviewed boundaries

- The production MapLibre module explicitly bundles and selects its worker URL;
  the browser fixture includes GeoJSON so an empty style cannot mask a missing
  worker. The full browser suite is run by the existing release workflow.
- Prepared spot images use the exact render input rather than re-reading a
  concurrently updated cache. Background preparation and display share that
  ownership; the former duplicated save was removed.
- Gzip buffer sizing stays inside compressed-cache I/O, not application policy.
- Missing forecast/marine retry completion accounts for storage failures; the
  worker's cadence remains the owner of retry timing.
- The test harness's production-source includes are isolated host adapters,
  allowing real embedded orchestration to run without adding test-only APIs to
  production firmware. HTTP, time, panel and locking remain explicit substitutes.
- No changed file crosses from below to above 1,000 lines. `wind_app.c` and the
  renderer were already larger than that before this change. Calendar ownership
  was improved in the canonical layer; a wholesale unrelated renderer rewrite
  is outside this release's changes. No new framework or pass-through module
  was added to disguise the existing size.

## Validation and release evidence

The ordinary 334-test host suite passes after the structural fixes. Full
sanitizers, both embedded targets, browser unit tests and the gated remote
release checks are recorded alongside publication evidence in
`2026-09-25-e1003-production-tests.md`.

These checks are evidence for the exercised behavior, not a guarantee of zero
firmware defects. Physical power-loss and unrestricted FreeRTOS interleavings
are not reproduced by the deterministic host harness.
