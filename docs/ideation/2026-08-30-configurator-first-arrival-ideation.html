Windpeek product entrance

Explain the transformation, not the controls

The configurator should remain the hero. The strongest direction adds one calm threshold inside it: this is free software, it turns a readily available reTerminal E1002 into a standalone wind forecast display, and the visitor can try the real result right now.

Date: 2026-08-30Topic: configurator-first-arrivalFocus: direct-landing comprehensionMode: repo-grounded

Grounding Context

Codebase Context. The Vue app mounts the full-screen configurator immediately. Its visible structure contains the 3D stage, settings, and on supported desktop browsers an Install continuation—but no product introduction. The repository’s clearest explanation says Windpeek turns a Seeed Studio reTerminal E1002 into a quiet, battery-efficient wind forecast dashboard that retrieves and renders data locally. The mobile experience deliberately keeps the demo interactive and gives the device meaningful screen space.

External context. Seeed’s official 2026 catalog lists the E1002 around $99–$109.99, so public copy should use “around €100” or “about $109” rather than an exact €100 promise. Apple’s discoverable-design guidance supports teaching through interaction and visual cues; its progressive-disclosure guidance supports showing just enough context to begin, then getting out of the way.

1The threshold card

First five secondsConfidence 93%Complexity Medium

Description. Let the live 3D device remain full-screen, but introduce it with a compact, non-blocking card integrated into the composition. As the copy appears, the screen can make one restrained transition from a stock/blank E1002 to the live Windpeek forecast: “This is a €100 e-paper screen. Windpeek turns it into your always-on wind forecast.” The card collapses after the visitor changes a setting or presses “Try it”; a small persistent “What is Windpeek?” control reopens it.

Stock E1002→Windpeek appears→Visitor changes spot→Card collapses
Axis
First five seconds
Basis
direct: the current page has no visible product framing, while the 3D scene is already the main stage and the README supplies a concise transformation story.
Rationale
It answers “what is this?” without putting a door in front of the strongest proof. The visual transformation communicates purpose faster than an explanation-only modal.
Downsides
Needs careful timing and responsive placement. The transformation should be subtle and skip or settle immediately under reduced-motion preferences.

2Make the first action the explanation

First interactionConfidence 86%Complexity Low

Description. Give the intro one invitation: “Choose your spot and see what your Windpeek would show today.” Selecting a spot changes the real forecast in the device, then the full settings surface takes over. The demo teaches both the value and the configurator in one action.

Axis
First interaction
Basis
direct: selecting a location already updates a live forecast, and the mobile product plan calls personal relevance core to the demo’s value.
Rationale
A location choice creates a small “that’s mine” moment. It is more persuasive than explaining every control and makes the tool’s purpose self-evident.
Downsides
Search must not become a gate; “Explore with Brouwersdam” should remain available, and mobile must not autofocus the keyboard.

3The three-step product journey label

First five secondsConfidence 84%Complexity Low

Description. Add a very short physical journey to the intro: “1. Buy a reTerminal E1002 · 2. Install Windpeek in your browser · 3. Put it down and glance at the wind.” Keep it human and outcome-led; technical details belong behind “How it works.”

Axis
First five seconds
Basis
direct: the product is firmware for a purchased E1002, the configurator already leads into browser installation on desktop, and the device operates independently after setup.
Rationale
It eliminates the biggest category confusion: this is neither a rendered concept device nor a €100 software purchase.
Downsides
Price and availability change. Use “around €100” and link the exact device rather than baking a guaranteed price into the core claim.

4A lightweight one-pager preview, not an embed

First interactionConfidence 78%Complexity Medium

Description. On the marketing one-pager, show the real device render with only one playful input—spot or wind threshold—and a clear “Configure yours” handoff. Open the full-screen tool with that chosen value carried across. Do not squeeze the complete inspector, map, and installation flow into an iframe-sized rectangle.

Axis
First interaction
Basis
reasoned: the 3D scene earns attention, but the complete configurator depends on generous viewport space and mobile-specific sheet behavior. A single authentic interaction proves reality without nesting a whole app.
Rationale
The one-pager gains the magic of the product while the configurator keeps its scale, performance budget, and clean URL.
Downsides
Creates a simplified second composition that must stay visually consistent. State handoff needs a small URL contract.

5Context-aware return without surveillance

Return pathConfidence 74%Complexity Medium

Description. Show the threshold card expanded for a genuinely new visit, but remember its collapsed state locally. A direct “What is Windpeek?” link can force it open; a one-pager CTA can arrive with it compact because that page already supplied context. No account or tracking profile is needed.

Axis
Return path
Basis
reasoned: first-time comprehension and fast repeat use are different needs. Local UI memory plus an explicit reopen control resolves the tension without making the content disappear permanently.
Rationale
This keeps the useful part of a first-run popup—different first and repeat states—without a blocking modal or an irreversible dismissal.
Downsides
Entry-state rules can become invisible complexity. Keep the matrix tiny: new/open, returning/collapsed, explicit-help/open.
